# Improvement plan

Tick the box on any idea you approve (or just reply with the IDs, e.g. "R1–R6, E1, Q3"). Every item keeps the current look: same colours, dashed drop zone, layout and fonts. Items that add anything visible say so under **Looks**. Effort: **S** < 30 min, **M** about an hour or two, **L** half a day or more.

My top picks if you only want a few: **R1, R2, R3, R5, E1, E2, Q1, Q3**.

**Shared origin:** `turquoise-turtle.github.io` also hosts `/pdf/` and other apps. Browser caches and local storage are shared across that whole site, so everything below that touches them stays strictly within `/zip/`: it only caches `/zip/` requests, only deletes caches with names starting `zip-`, and only uses storage keys starting `zip:`.

## Reliability

- [x] **R1. Show an error when a zip can't be read (S).** `zip.loadAsync(...)` in [alt.js](alt.js) has no `.catch`, so a corrupt, password-protected or non-zip file fails silently and nothing happens. Catch it and show a short message in the drop zone ("Couldn't open this zip: it may be damaged or password protected"). Do the same for `generateAsync`. **Looks:** a one-line message in the existing drop zone text.
- [x] **R2. Fix the service worker failing on cache misses (S).** `fromCache` in [service-worker.js](service-worker.js) rejects with `'no-match'` when a request isn't cached, so anything not precached gives a network error. This includes `/zip/` itself, since only `/zip/index.html` is precached. Fall back to `fetch()` on a miss, and precache `./` as well. Requests outside `/zip/` go straight to the network and are never stored in zip's cache.
- [x] **R3. Version the cache and clean up old ones (S).** `CACHE` never changes, so returning visitors always get the copy one version behind, and old caches are never deleted. Rename the cache to a prefixed, versioned name (e.g. `zip-v2`). In an `activate` handler, delete only caches whose names start with `zip-` and aren't the current one; `/pdf/` and the other apps' caches are never touched. Call `skipWaiting()` and `clients.claim()` so a fix (like the one just made) reaches users on their next visit.
- [x] **R4. Stop the service worker caching bad responses (S).** `update()` caches every response: 404s, 500s, non-GET requests (where `cache.put` throws), and even the `makerwidget.com` requests that `doNotCache` is supposed to skip. It also fetches those twice. Only cache successful GET responses for URLs under `/zip/` (the worker's own scope, not just the same origin), and skip `update()` entirely for do-not-cache URLs.
- [x] **R5. Keep non-English filenames intact (M).** Zips made by Windows' built-in "Send to → Compressed folder" store names in the old DOS code page, not UTF-8. JSZip decodes them as UTF-8, so names like `Résumé.docx` or Japanese filenames come out garbled in the *output* zip, because the whole zip is rewritten. Pass a `decodeFileName` option that falls back to CP437 or `TextDecoder` when the UTF-8 flag isn't set.
- [x] **R6. Keep file permissions (S).** `generateAsync` defaults to `platform: 'DOS'`, which drops Unix permissions, so executable scripts or apps inside the zip stop being executable after cleaning. Generate with `platform: 'UNIX'` when the source entries have `unixPermissions`.
- [x] **R7. Match Mac junk by path segment, not substring (S).** `filename.indexOf('.DS_Store')` also removes legitimate files like `notes.DS_Store.txt` or a folder named `my__MACOSX/`. Use the same per-segment matching the Windows fix now uses.
- [x] **R8. Make the "remove from filename" option robust (S).** `name.replace(query, '')` removes the *first* match anywhere: `my-raw-files-raw.zip` becomes `my-files-raw.zip`. The contenteditable also turns spaces into `&nbsp;` and Enter into a newline, so the text silently stops matching. Trim and normalise the text, strip it only from the end of the name (before `.zip`), and never produce an empty name.
- [x] **R9. Stop a stray drop from opening the zip (S).** Drop handlers are only on `.container`. Dropping just outside it makes the browser navigate to or download the raw zip, which loses the page. Call `preventDefault` on `dragover`/`drop` for the whole window.
- [x] **R10. Let you pick the same file twice (S).** The file input keeps its value, so choosing the same zip again (e.g. after toggling the rename option) doesn't fire `change`. Reset `fileElem.value` after each run.
- [x] **R11. Validate drops (S).** `accept=".zip"` only applies to the picker. Dropping a `.png` or several files silently processes `files[0]`. Check the type or extension and say what happened. This pairs with Q6 if you want several zips handled at once.
- [x] **R12. Upgrade JSZip 3.1.5 → 3.10.1 (S).** It includes years of bug fixes, a fix for crafted zips that use `../` paths and `__proto__` names (CVE-2021-23413), and better Zip64 reading. It's a drop-in replacement for the bundled file.
- [x] **R13. Add a small automated test (M).** *Done as a full Playwright suite across Chromium, Firefox and WebKit, checked with Python's `zipfile` and Info-ZIP's `unzip`.* A `node --test` script, using a small `uv run` Python fixture generator, that builds zips like the one I used to verify the fix (Mac, Windows names, hidden attribute, hidden folders, Unicode names) and checks what `isHidden` keeps. A GitHub Action could run it on PRs, since the repo invites contributions.

## Efficiency

- [x] **E1. Keep the output compressed: it's currently stored uncompressed (S).** `generateAsync({type: "blob"})` defaults to `compression: "STORE"`, so a 50 MB zip of text can come back several times larger. Use `compression: "DEFLATE"`. This also makes it **faster**: when output and input compression match, JSZip copies the already-compressed bytes straight through instead of decompressing every file (I checked this in the bundled `jszip.js`).
- [x] **E2. Remove the third-party widget (S).** The `makerwidget.com` script at the bottom of [index.html](index.html) (the "Check out my team" badge) is an extra network request on every visit, sends visitor data to a third party, and fights with the service worker. Dropping it makes the page fully self-contained. **Looks:** the small bottom-left badge disappears. *(If you're not the repo owner, this is their call.)*
- [x] **E3. Do the zip work in a Web Worker (M).** Loading and generating run on the main thread, so the tab freezes on large zips and the browser may show "page unresponsive". Moving JSZip into a worker keeps the page responsive and enables a progress bar (Q2).
- [x] **E4. Build the file lists in one go (S).** Each `<li>` is appended to the live DOM separately, and zips with thousands of entries cause visible jank. Build into a `DocumentFragment` and append once. Optionally cap the visible list at around 1,000 rows with a "+N more" line.
- [x] **E5. Skip rewriting when nothing is hidden (S).** If no entries are removed, the zip is still fully rebuilt and downloaded. Skip the rebuild, and either say "Nothing to remove" (see Q4) or hand back the original file unchanged.
- [x] **E6. Remove entries in one pass (S).** `zip.remove()` on a folder scans every entry in the zip, so zips with many hidden folders (e.g. deep `__MACOSX/` trees) do O(n²) work. Collect the paths to drop first, then delete them from `zip.files` directly.
- [x] **E7. Quieten the service worker logs (S).** `doNotCache` and `fromCache` `console.log` on every request, which adds noise and a little overhead. Remove them, or put them behind a `DEBUG` flag.
- [x] **E8. Use relative paths instead of hard-coded `/zip/` (S).** Registration and precache URLs assume the site lives at `/zip/`, so forks, custom domains and local testing get a broken service worker. Use `register('service-worker.js', { scope: './' })` so the code states plainly that the worker covers `/zip/` only, and make the precache paths relative to the worker's scope.
- [x] **E9. Drop FileSaver.js (S).** Every supported browser now handles `<a download>` with a Blob URL. A five-line helper (which also revokes the object URL to free memory) replaces the 6 KB library. Alternatively, upgrade it to 2.0.5.
- [x] **E10. Remove dead files (S).** `main.js` (an abandoned experiment, noted in its own header), `code.txt` are never loaded but still clone and deploy. Delete them and then reuse `zip.png` as the app icon for Q10.
- [x] **E11. Stream very large zips (L).** *Done differently: kept entries are copied byte for byte as slices of the original file, so no streaming library was needed (see `.agent/DECISIONS.md`).* Everything is held in memory at least twice, so multi-GB zips crash the tab, and JSZip can't write Zip64 (outputs over 4 GB). Switching to a streaming library (`fflate` or `zip.js`) combined with the File System Access API's streaming writes lifts that limit. This is the biggest change on the list; only worth it if large zips matter to you.

## Quality of life

- [x] **Q1. Handle more junk files (S).** Mac: `._*` AppleDouble files *outside* `__MACOSX` (made when copying to USB/exFAT drives), `.Spotlight-V100/`, `.Trashes/`, `.fseventsd/`, `.TemporaryItems/`, `Icon\r`. Linux (the README asks for this): `.Trash-*/`, KDE's `.directory`, `.nfs*`. Windows is now covered by the issue fix.
- [x] **Q2. Progress indicator (M).** Use `generateAsync`'s `onUpdate` callback to show a percentage in the drop zone text while big zips process. **Looks:** text only ("Cleaning… 42%") in the existing box; no new elements.
- [x] **Q3. Highlight what was removed (S).** The two lists are hard to compare by eye. Mark removed entries in the Original list (strike-through or muted), and add a summary like "Removed 9 of 14 items, 2.1 MB smaller". **Looks:** strike-through on removed rows plus one summary line.
- [x] **Q4. Clear "nothing to remove" feedback (S).** When the zip is already clean, say so instead of silently downloading an identical copy.
- [x] **Q5. Remember your settings (S).** Save the "Remove `-raw`" checkbox and text in `localStorage` so they survive reloads. Keys are prefixed (e.g. `zip:renameEnabled`) because `/pdf/` and the other apps share the same storage.
- [ ] **Q6. Clean several zips at once (M).** Accept multiple files from the picker or a drop, and process each one, downloading each result. The lists could show the last one, or one pair per zip.
- [ ] **Q7. Choose what to remove (M).** Small checkboxes for Mac, Windows and Linux junk, all on by default, styled like the existing rename checkbox. Useful when someone wants to keep, say, `desktop.ini` folder icons. **Looks:** one extra row of checkboxes under the rename option.
- [x] **Q8. Explain why each item was removed (S).** A `title` tooltip on removed rows, e.g. "macOS resource fork" or "Windows thumbnail cache", so people trust what was taken out.
- [x] **Q9. Keyboard and screen-reader access (S).** The real `<input>` is `display: none`, so you can't Tab to the drop zone, and the contenteditable has no label. Use a visually-hidden (still focusable) input with a focus outline matching the hover colour, and swap the contenteditable for a styled `<input type="text">` that looks the same. Also fix the nested `<label><label>` markup. **Looks:** identical, apart from a focus ring when tabbing.
- [x] **Q10. Make it installable as an app (S).** The service worker already makes it work offline. Add a `manifest.json` (name, `#336B87` theme colour, icon) so it can be installed to the dock or home screen. Its `scope`, `start_url` and `id` are set to `/zip/`, so the installed app only opens `/zip/` pages and links to `/pdf/` open in the browser instead. Also and mention "works offline; files never leave your device" in the small print. **Looks:** one extra sentence in the existing italic note.
- [x] **Q11. Proper page skeleton and mobile view (S).** [index.html](index.html) has no `<html>`, `<head>`, `<body>`, `<meta charset>` or viewport tag, so phones render it zoomed out at desktop width. Add those, and stack the two lists vertically on narrow screens. **Looks:** unchanged on desktop; readable on phones.
- [x] **Q12. "Download again" link (S).** After a run, keep the cleaned blob and show a small "download again" link, so you don't have to re-pick the file if the download was blocked or saved to the wrong place.
- [x] **Q13. Update the README (S).** List exactly what gets removed on each OS, note the offline and privacy behaviour, and remove the "add Windows/Linux support" request now that it's done.
- [x] **Q14. Add `.editorconfig` (S).** Lock in the repo's style (tabs, tab-indented blank lines, LF) so editors and contributors match it automatically.
- [x] **Q15. Set Language to en-AU.** Make sure that any language codes and spellings are in en-AU
- [x] **Q16. Zip a folder without its hidden files (M).** Progressive enhancement: desktop browsers can pick or drop a folder and get a zip without the junk. Not offered on phones and tablets, which claim folder support but can't pick folders. Compresses with `CompressionStream` where available, otherwise stores. **Looks:** one extra line, "or choose a folder to zip without them", in the drop zone.
- [x] **Q17. Folder zipping upgrades (M).** Approved after comparing libraries (see `.agent/research-zip-libraries.md`): keep our own zip code, and add (1) streamed downloads through the service worker where the browser supports it, so nothing is held in memory and big files are compressed too, (2) a probe that adapts the number of file references to each browser instead of a fixed cap, and (3) a CRC-32 that's 4 to 8 times faster.
